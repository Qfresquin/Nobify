## Parity Governance

The evaluator product/runtime must not depend on CMake. CMake 3.28 is allowed
only as a differential test oracle.

`FULL` means audited CMake 3.28 parity for the row, not "a native handler
exists" and not "the implementation looks complete". A row can be `FULL` only
when executable evidence covers the relevant documented forms, observable
variables/properties, diagnostics and control-flow outcome, policy-sensitive
behavior, and emitted Event IR or downstream semantic state.

Commands are governed as:

- `CMAKE_ORACLE_TESTED`: native Nobify evaluator behavior is checked against
  CMake 3.28 in tests.
- `NATIVE_PROVEN`: native implementation has strong differential or special
  oracle evidence and no tracked known divergence.
- `NATIVE_PARTIAL`: useful native implementation, but no full parity promise.

New native handlers start as `NATIVE_PARTIAL` in the audit manifest. Promotion
to `FULL` requires positive differential evidence or an approved host/special
oracle. A `FULL` row with no executable evidence, or with a known divergence
key, is a test failure.

`PARTIAL` rows must use granular known-divergence keys such as
`math.overflow_wrap_and_literal_08` or `block.propagate_unset`. Generic
`partial.audit.<command>` keys are intentionally rejected because they cannot be
promoted or retired one behavior at a time.

`EPM_EVIDENCE_KNOWN_DIVERGENCE` is reserved for executable inverted cases in
`known_divergence_seed_cases.cmake`. `EPM_EVIDENCE_INTERNAL_ONLY` means the row
is still `PARTIAL`, but the current reason is not yet an observed CMake
mismatch; it needs a focused oracle case before it can be called a known
divergence.

## Differential Program

- Runner: `./build/nob test evaluator-diff`
- CMake resolution: `CMK2NOB_TEST_CMAKE_BIN`, then `PATH`
- Version gate: only `cmake 3.28.x` participates; otherwise the suite skips
- Optional report output: `NOB_DIFF_STATUS_OUT=/abs/path/report.md`
- Supported lanes:
  - `snapshot differential`
  - `host-effect differential`
  - `normalized failure differential`
  - `special oracle lane`
  - `known divergence lane`
- Current phase status:
  - Phase 1: closed
  - Phase 2: closed
  - Phase 3: closed for deterministic local host effects
  - Phase 4: closed for special-oracle families
  - Phase 5: closed for structural/policy surface
  - Phase 6: closed by explicit row ownership in this matrix
  - Phase 7: closed for pinned CI coverage and per-family status reporting
- Operational rule: every row in the audit matrix must have exactly one primary
  differential lane and one primary differential owner
- Harness details, DSL, snapshot format, and failure artifacts live in
  [test_v2/evaluator_diff/README.md](../../test_v2/evaluator_diff/README.md)
- Known divergences live in
  [known_divergence_seed_cases.cmake](../../test_v2/evaluator_diff/cases/known_divergence_seed_cases.cmake)
  and are inverted: matching CMake is a test failure until the manifest row is
  promoted and the case moves to a positive diff pack.
- Dedicated CI coverage lives in `.github/workflows/evaluator-diff.yml` and
  stays separate from the default smoke aggregate

## Ownership Notes

- `file` is owned primarily by `file_host_effect`; the script-mode snapshot
  subset remains covered by `file_script`.
- `FetchContent_*` is owned primarily by `fetchcontent_host_effect`; provider
  bridge coverage also exists through `dependency_provider` and
  `find_package_special`.
- `cmake_language` is owned primarily by `cmake_language_script`; provider-only
  bridge scenarios remain additionally covered by `dependency_provider`.
- `cmake_policy` is owned primarily by `cmake_policy_script`; structural policy
  interactions are additionally covered by `structural_policy_compat`.
- `configure_file` is owned primarily by `configure_file`; script-mode coverage
  also exists in `configure_file_script`.
- `enable_language_special`, `legacy_cpack_failure`, `legacy_loader_failure`,
  and `legacy_compat_failure` now have dedicated seed packs so manifest
  `evidence_pack` values point at executable differential cases instead of
  documentary-only owners.
- Several legacy-meta rows remain registry-`FULL` for compatibility with the
  native command registry, but their audit status is `PARTIAL` until the
  evaluator emits typed semantics or an explicit unsupported/reject contract
  replaces the current `NOBIFY_LEGACY::*::ARGS` projection.
